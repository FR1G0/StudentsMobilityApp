Users:
id : ID PK AUTO_INCREMENT
email : VARCHAR(255) UNIQUE NOT NULL
password_hash : VARCHAR(255) NOT NULL
role : VARCHAR(50) NOT NULL
first_name : VARCHAR(100) NOT NULL
last_name : VARCHAR(100) NOT NULL
matriculation_number : VARCHAR(50) DEFAULT NULL

The decision to consolidate all users into a single table with a `role` field handles authorization cleanly, since "The system must manage at least three types of users: 1. students... 2. referent lecturers (docenti referenti)... 3. overseas office staff". The `matriculation_number` row is nullable because it specifically applies to the student role.

---

HostInstitutions:
id : ID PK AUTO_INCREMENT
name : VARCHAR(255) NOT NULL
country : VARCHAR(100) NOT NULL
city : VARCHAR(100) NOT NULL

This row structure directly fulfills the core administrative entity requirement: "The system must contain a predefined list of partner institutions. Each institution must have at least a name, country, and city.".

---

MobilityApplications:
id : ID PK AUTO_INCREMENT
student_id : ID FK(Users)
institution_id : ID FK(HostInstitutions)
lecturer_id : ID FK(Users)
academic_year : VARCHAR(20) NOT NULL
expected_period : VARCHAR(50) NOT NULL
status : VARCHAR(50) NOT NULL
actual_arrival_date : DATE DEFAULT NULL
actual_departure_date : DATE DEFAULT NULL
rejection_reason : TEXT DEFAULT ''

Foreign keys link the single student creator, host university, and academic reviewer because "Each application refers to a single host institution, chosen from a predefined list of partner institutions, and a single referent lecturer at Ca' Foscari.". The `status` row acts as the state driver to enforce that "Each application must have an overall status...". Nullable date fields are included because "The student indicates the actual arrival and departure dates at the host institution." only during the second stage of mobility.

---

ExamMappings:
id : ID PK AUTO_INCREMENT
application_id : ID FK(MobilityApplications)
foreign_code : VARCHAR(50) NOT NULL
foreign_name : VARCHAR(255) NOT NULL
foreign_credits : INT NOT NULL
cafoscari_code : VARCHAR(50) NOT NULL
cafoscari_title : VARCHAR(255) NOT NULL
cafoscari_credits : INT NOT NULL
score : VARCHAR(20) DEFAULT NULL
exam_date : DATE DEFAULT NULL
is_approved : BOOLEAN DEFAULT FALSE
status : VARCHAR(50) NOT NULL DEFAULT 'active'

The text fields and integer credit rows map the corresponding values directly from the student's program requirements: "foreign teaching code; name of the foreign course; credits for the foreign course; course code in the study plan at Ca' Foscari; title of the course in the study plan at Ca' Foscari; teaching credits in the study plan at Ca' Foscari;". The `score` and `exam_date` fields are set to default null because they remain empty until the third phase when the student "updates the list of exams with the score obtained and the date on which the exam was taken.". The `status` column handles rollback operations when mapping modifications are rejected by a lecturer.

---

Documents:
id : ID PK AUTO_INCREMENT
application_id : ID FK(MobilityApplications)
file_type : VARCHAR(50) NOT NULL
file_path : VARCHAR(512) NOT NULL
version : INT NOT NULL
upload_date : TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP

The row tracking `version` and `upload_date` satisfies the auditing requirement to "Provide a history of files uploaded as Learning Agreement and Transcript of Record, with the upload date of each version.".

---

ModificationRequests:
id : ID PK AUTO_INCREMENT
application_id : ID FK(MobilityApplications)
description : TEXT NOT NULL
status : VARCHAR(50) NOT NULL DEFAULT 'pending'
decision_date : TIMESTAMP DEFAULT NULL
rejection_reason : TEXT DEFAULT ''

This separate entity isolates proposed variations from the active application data, ensuring structural compliance when "The student may propose one or more modifications to the exam mapping during the mobility period. Each modification contains a textual description.". It also logs the outcomes when "The referring lecturer must be able to approve or reject each modification, recording the date and, if applicable, a reason.".
